# v0.2 local cash table acceptance

Date: 2026-09-29. Scope: C1 cash browser flow and L1 local boundary. L1 commit: `c293d00dc85b93af8a876fa2090851809990a091`; C1 engine commit: `2497cd6e20d76bd0dd448d7b840c291899e79ffc`.

## Delivered

- Local NLHE cash setup: 2–6 visible seats, at most one named human, integer small/big blinds, adjustable 20–500BB buy-in depth, top-up threshold, optional human auto top-up, and no rake. The smallest chip unit is one integer chip; the UI does not imply real currency.
- Fixed blinds across hands. Bots top up between hands when below the threshold or empty; the human follows the configured auto policy and can top up manually between hands. Each seat's buy-ins and top-ups add to `cashInvested` and the transaction list. Stats shows `net = current stack - cashInvested`.
- Pause after the current hand, resume, end session, and new session. Cash tables with fewer than two funded seats wait rather than declare a champion. A human with no chips and auto top-up disabled must top up before another hand.
- Existing continuation snapshot now includes cash config, ledger and seat investment. The original tournament engine path remains the default for states without `gameMode: "cash"`; the restore path treats old one-human snapshots as tournament states, though that older-browser-snapshot path was not separately exercised here.
- All automatic external resources and original table sync are disabled. A same-origin Content Security Policy covers the main and companion pages. The service worker precaches `js/version.js` along with the other local assets.

## Verification

- Node `Deno.test` shim: 66/66 passed. Deno itself is not installed. `node --check` for changed JS and `git diff --check` passed.
- `node evidence/cash-smoke.mjs`: 1,000 seeded six-bot cash hands at 50/100, 100BB, with 88 top-ups; no invalid actions, unchanged blinds, and per-hand `sum(stacks) = sum(cashInvested)` with no rake.
- Browser six-seat run at 5/10 and 60BB: initial stacks were 600; second hand kept 5/10. Pause blocked New Hand; manual top-up of 10 changed Hero from 590 chips/600 invested to 600 chips/610 invested, and Stats reported net −10. Mid-hand refresh offered Continue and restored the 5/10 cash setup and stacks. End Session exposed New Session and results. No app console warnings or errors appeared.
- Fresh 127.0.0.1 test origin: service worker installed and cached the local assets. After the local HTTP server stopped, the browser reloaded from cache, started a two-seat 10/20, 20BB game, and completed a hand: 400/400 became 390/410 with pot zero and New Hand available. The browser logged an expected service worker update-fetch error because the server was intentionally stopped; the game ran normally.

## Boundary and next input

This is a cash-table preview, not yet a long-term training release. The original bots still contain tournament strategy assumptions; Q1/B1 will measure and adapt them. O1 must add seat-private observations and a guarded action entry; H1 must add immutable, exportable hand records. The current localStorage snapshot is continuation state, not a hand-history database.
