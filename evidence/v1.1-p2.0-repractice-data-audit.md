# P2.0 Repractice data audit — 2026-09-30

## Gate result

**Go for a limited `similar_sample` exercise. No-go for an `original_hand_branch`.** A completed hand can be replayed as a record of what happened. It cannot be resumed at an old decision with the original hidden state. P2.1 must label each new deal as a new sample and keep its results separate from free-table cash results.

## What the existing hand record proves

| Data | Source | Usable at an old decision? |
|---|---|---|
| Session/hand IDs, dealer, blinds, chip unit, ordered seats, starting stacks, bot style/version, and before-hand top-ups | `createHandHistory` header in `js/shared/handHistory.js` | Yes. These describe the original table setup. |
| Posted blinds, dealt board, public actions with amounts and order, revealed cards, returns, payouts, ending stacks | `events` in `js/shared/handHistory.js` | Yes, for events already reached. Later events are excluded from a decision's view. |
| Pot, street bets, stacks, contributions, folded seats, known hole cards at an event prefix | `replayHandHistory(history, throughSeq)` | Yes, for an **observed past state**. An action's `seq - 1` is the point before that recorded action. |
| The human's hole cards | `hole.dealt` and seat projection | Yes when a human seat exists; they are a source description, not a card requirement for a new sample. |
| Unrevealed opponent cards | Local full record may contain them, but `projectSeatHandHistory` and JSON backup replace them with `null` | No. A practice filter must never use them. |

`action.applied` is logged **after** the choice. There is no `decision.started` event. A marked decision can use the human `action.applied` event as its anchor and compute the visible prefix at `seq - 1`, but that prefix is not a saved engine snapshot.

## Missing state and claims we cannot make

- Hand history has no remaining deck order, burn cards, `Math.random` state, or old future draws. `dealHoleCardsForNewHand` shuffles with `Math.random`; community dealing consumes burns. A current-session local save has a deck, but it is a single mutable continuation snapshot, not an archive of old decisions.
- It has no decision-time bot private memory, cumulative stats, `botLine`, `spotState`, hand context, betting-round cursor, or per-player raise rights. The current save contains some of these only for the current point in the live hand. A visible event prefix cannot reconstruct a fully equivalent bot/engine state.
- History does not encode the counterfactual response to an alternate action. The original opponent and board runout cannot be promised after a changed choice.

Therefore `original_hand_branch` is **unavailable** for schema v1 histories, including imported backups. It should not appear as a selectable mode. Adding only a seed in a future schema would still be insufficient for old hands and for bot internal random calls.

## First repeatable scenario

P2.1 is limited to the **human's first preflop voluntary decision in an unopened pot**, with any earlier players having folded. The source action is located by its `seq` and `decisionId`; only a human action is eligible. The visible event prefix must consist of both blinds, all hole-deal events, and zero or more ordered preflop folds. A short blind all-in, an earlier call/raise, missing human hole cards, or any postflop decision is outside this first scope.

Repeatable filters are: seat count and clockwise dealer-relative human position, each seat's starting stack in chips and BB, blind/chip-unit values, bot styles at the seats, and the ordered prior folds. The decision's pot and amount to call are verified from the event prefix. Hero cards are **newly dealt**, not held equal to the source; opponents' cards and future board are newly dealt. Bots begin with reset per-hand state and make new random choices after the marked decision. These filters define a similar spot, not an exact game-state copy.

Each practice sample needs a `similar_sample` mode label, source hand key and decision sequence, recorded filters, a unique sample identity, and an explicit reset/new-deal event or record. Free-table bankroll and its saved continuation must not be reused or overwritten. No bot action, outcome, or exercise result is a strategy grade or GTO score.
