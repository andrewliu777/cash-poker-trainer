# v1.1.1 out-of-chips top-up prompt — 2026-09-30

## Scope

With automatic top-up off, a cash player who ends a hand at zero chips sees a focused prompt to refill to the configured buy-in. Choosing Not now leaves the table between hands; choosing New Hand while still unfunded opens the prompt again. The existing manual top-up plan remains the single rule and accounting path.

## Checks

- `node --check js/app.js` and `git diff --check`: passed.
- Five test modules with the Node test shim: 90 passed, 0 failed. Existing cash tests cover manual top-up transactions and the separate automatic top-up behavior.
- HTML ID check: 86 unique IDs.
- Browser on an isolated local port with six seats, 10/20 blinds, 20 BB buy-in, and automatic top-up off: Hero lost a preflop all-in and ended with zero chips. The prompt displayed a 400-chip refill. Not now closed it; New Hand reopened it; Top up 400 restored the stack to 400 without dealing. A subsequent New Hand dealt normally. No browser console warnings or errors.
- Prompt has a labelled dialog, visible keyboard focus, two 44px-minimum buttons, and a contained Tab cycle.

## Limits

The prompt applies to a human at zero chips in manual top-up mode. Automatic top-up and bot refills keep their existing behavior. The browser run did not include a reload while busted; that path is wired to the same prompt from the saved between-hand flow.
