# D0.5 IkaSolver due diligence — 2026-09-30

## Decision for the cash trainer

**Research candidate for manual six-player postflop study; not a proven automated grading backend.** IkaSolver's own documentation describes 2–9 player trees starting on the flop, turn, or river, a headless solver CLI, and combo-level action frequencies/EV in its GUI. This supports a plausible *manual* six-active-player test. It does not establish that the trainer can create a `.tree`, read a solved `.iks`, or grade each arbitrary hand through a supported, licensed interface. No six-active-player NLHE postflop solve with published tree/ranges, hardware, wall time, RAM and independent quality check was found in the reviewed public material. No licence, binary, sample file or solve was obtained for this investigation.

The earlier D0.4 phrase "best automation research candidate" was too broad. Ika has documented CLI solve input, but no documented postflop result API; the later-discovered [Prism Solver](https://prismsolver.com/) claims JSON spot input and reports, although its free Viewer cannot solve and its full solver remains a paid beta. Ika must not be read as an end-to-end integration recommendation.

Its later bounty-mode bug-fix note should not be used to infer NLHE accuracy either way.

## Practical fit and proof gate

The current trainer is a static browser app. An installed solver CLI cannot be invoked from `file://` JavaScript. Even if `.tree` construction and `.iks` output were supported, automatic scoring would require a local companion service or an authorised remote service, plus an exact mapping from the trainer's decision snapshot to the vendor tree node. Arbitrary hand history alone does not identify opponents' hidden ranges; EV would have to be labelled conditional on explicit range assumptions, abstraction, action tree and solve settings.

Before making IkaSolver the D3 backend, obtain a supported method to (1) create a six-player postflop `.tree` with exact board, pot, stacks, ranges and action sizes; (2) extract every action's EV for the hero's exact combo and target node from a postflop solve; and (3) use that workflow within a private trainer under the licence. Then solve one six-active-player **river** trainer fixture and record tree/ranges, binary version, CPU/RAM, `--ram` estimate, peak memory, wall time, iterations, volatility, all action EVs and independent repeat/abstraction sensitivity. Repeat at 20bb and 100bb, then turn and flop. If an action is off-tree, a range cannot be represented, or result access is unsupported, return `unavailable` rather than a guessed grade.

**Current D3 status: No-Go for automatic IkaSolver grading.** It remains a plausible commercial engine for manual experimentation, contingent on access to a licence and a real fixture. The investigation made no purchase and did not contact the vendor.
